01 / ARCHITECTURE

Hardware Display Architecture

LoRaTrace RX executes on the M5Cardputer-Adv (ESP32-S3FN8). The display is an ST7789V2 driven over dedicated SPI. The system is strictly budget-constrained: 512KB SRAM with zero external PSRAM.

Dedicated Core 0 UI Thread

The UI task runs on Core 0 and redraws at ~10-20Hz. The SX1262 radio task runs strictly pinned to Core 1 and never blocks on display SPI, SD logging, or keyboard I/O.

Zero-Allocation Rendering

Every page draw function (drawRadioPage, drawActivityPage, etc.) executes with zero dynamic heap allocations. Memory is pre-allocated or statically budgeted in task stacks.

No Full-Screen Blanking

drawPage() wipes only the content canvas (HEADER_H to FOOTER_Y) and performs direct overwriting. Full fillScreen() calls are banned during page transitions to eliminate visible black flashes.

Fixed-Pitch Bitmaps

Uses Adafruit-GFX / M5GFX built-in bitmap fonts: Size 1 is 6×8px (up to 40×16 chars); Size 2 is 12×16px (up to 20×8 chars). All positions are integer-aligned.

03 / GEOMETRY

Screen Layout & Character Grid

Display area is strictly 240×135 pixels. The layout is divided into three fixed horizontal zones:

Header Chrome: y=0..12

Height 12px. Contains breadcrumb / page title (left, max 25 chars size 1), status dots (x=155..177), and battery icon with % (x=214..238). Border hairline at y=12.

Content Canvas: y=13..124

Height 112px. Where all page-specific UI widgets, tables, graphs, and statistics are drawn. Standard left column starts at x=2; right column aligns at x=170.

Footer Bar: y=125..135

Height 10px. Anchors active profile name at x=2 (e.g. Meshtastic) and carousel position at right (e.g. [1/5]). Replaced during menu display.

04 / CHROME

Header Chrome & Battery Anatomy

Drawn on every page by drawHeader() and drawBattery(). The 25-character breadcrumb limit guarantees that deep menu paths never collide with the status dots cluster.

Status dots (2026-09-06). Four now, shifted left to x=148 so the fourth fits clear of drawBattery(), which clears from x=184: WiFi AP, GPS fix, heap health, RX activity. WiFi moved here from System's bottom line — a binary state belongs in the cluster that already exists for exactly that, and the client count moves to the web UI and the toggle toast, which a dot cannot carry and does not need to. The menu breadcrumb cap dropped 25 → 23 characters to clear it.

The plot well. Cards whose band is a plot draw left and right rails and a floor, with the header's own hairline as the top edge — a full box put a second horizontal line 2px below one already there. The rails meet it at x=0 and x=239, so the band reads as a compartment carved out below the header. The floor doubles as the plot baseline. Radio's grid and Channel's axis use it too; only Channel shortens it, to 28px, because an axis is not a plot.

05 / NAVIGATION MODEL

Card Views — the Two Axes

The structural change of 2026-09-05/06. There is exactly one navigation system. The carousel has five cards; each card owns an ordered list of views. Left/right (, /) moves between cards, up/down (; .) cycles the current card's views, and Enter runs the bounded action that refreshes whichever view is showing. A card owns a question; its views answer that question at different resolutions.

Every page in plates 06–19 is one card view. None of them is a separate destination: the Tools and Analyze menu groups that used to open them standalone were removed, because a card view already went to the same place and having both on screen was the "two separate navigation systems" complaint in a third costume. Nothing is reachable without a carousel position.

07 / RADIO · VIEW 2

Plate: METER (Live Signal Level)

Radio view 2. Not a bounded action, so it takes the carousel cards' shape — gauge in a well, three cards — rather than the result skeleton Probe/Sweep/Cell/Focus share.

Its two sources (a live Scope sample, or the newest decoded packet) used to duplicate the entire layout between them; they now differ only in their cards, which is the only thing that actually differs. Scope reports no SNR: it samples raw RSSI at one frequency without demodulating anything, so it genuinely has none — an honest omission, the same rule as Waterfall's "no fabricated vertical texture".

The gauge runs −120..0 dBm, not Scope's −120..−30: real readings from a close repeater hit −16dBm and clipped flat against the old ceiling.

08 / RADIO · VIEW 3

Plate: SCOPE (Time-Domain RSSI)

Radio view 3, and the one page whose mere arrival requests a radio action — entering it starts a bounded SCOPE_ACQUIRE, gated on the keyboard being present so a headless unit's auto-advance carousel never pauses Watch on its own.

Leads with the frequency rather than the state word (2026-09-06): what a trace is of is the durable fact, where CAPTURING/CAPTURED is momentary. The result age takes the top right — once a trace is on screen "CAPTURED" is self-evident and its age is not; while running that slot carries the live state instead, which is the one time it is news.

Never a spectrum and never a decode: this is raw RSSI at one tuned frequency, sampled on a fixed interval. The display range is fixed at −120..−30 so two captures' trace heights stay comparable, which is a different job from Meter's "show the real range without clipping" and is why the two do not share constants.

13 / CARD 3 · CHANNEL

Plate: CHANNEL (Tuning & Yield)

Card 3, view 1 of 4 (Probe, Captures and Nodes are 2–4). A 28px well rather than the shared 45: this band is an axis with ticks, not a plot, and the reclaimed height goes to the frequency hero — the one number this card exists to state.

The well floor doubles as the frequency axis, so the ticks rise from it and the map draws no track of its own. Green marks frequencies that actually decoded a packet, amber peaks the last Sweep found; a capture draws over a peak on a shared bin, because a decode is stronger evidence than energy. The card is titled DECODED, not YIELD: the radio keeps one counter for the whole power-on and a profile switch does not reset it, so "yield" would claim an attribution the number cannot support.

19 / CARD 5 · SYSTEM

Plate: SYSTEM (Endurance)

Card 5, the one single-view card. "Will the device survive the drive" is a question about a trend, and every value here used to be an instant — a slow leak and a healthy idle looked identical until one of them wasn't.

Heap and battery get a lane each rather than being overlaid: they share nothing but a time axis, so one plot meant a line wandering across an area at an unrelated scale. Both lanes auto-scale with a minimum span, which is the other half of it — pure min/max scaling amplifies a 2KB wobble to full height, so a perfectly flat heap looked alarming. With a floor on the span, flat reads flat.

The BATTERY subtitle is a measured discharge rate over a stated window, not a projected runtime. docs/research/V2_DESIGN.md §3 forbids presenting derived confidence as measurement, and "~4h left" is a projection dressed as a reading.

20 / NAVIGATION

Plate: Menu Hierarchy & Sliders

Grouped hierarchical menu with inverted color selection bars (24px row pitch) and live interactive slider widgets (e.g. ST7789V2 LEDC backlight brightness).

Reduced to three root rows on 2026-09-06. Tools and Analyze were removed: every row in them opened a page that is now a view of the card that owns it, so they were a second road to somewhere you were already standing beside. What remains is what a menu is actually for — things that change runtime behavior and have no card of their own. Trace returns to a root row, where it lived before Tools briefly adopted it: it is a Watch pause, not a page, and Enter-on-Radio is a binding, not a label.

Cardputer TCA8418 Key Matrix

Driven via TCA8418 I2C keyboard scanner. Four primary navigation keys form an inverted-T cluster, supplemented by Enter, Back, and direct single-key shortcuts. The two axes are the whole model: , and / move between cards; ; and . move within one.

Future UI Evolution & Proposals

Identified improvement areas and candidate enhancements under evaluation for Workstream 12–15:

Direct Sunlight Contrast

COL_DIM (~75% grey) provides sufficient outdoor contrast while preserving visual hierarchy. High-contrast monochrome mode is under evaluation for high-glare environments.

Workstream 12 Focus Visuals

Adding dedicated single-bin dwell and statistical distribution indicators (P90/P50/Floor) when Workstream 12 transitions to production.

Activity Hero State Refinement

Maintaining clear hero status during active background scans while preserving instant access to last-result telemetry when idle.

Waterfall Persistence

Evaluating optional ring buffer persistence to SD for long-term RF landscape comparison across wardrive sessions.
