# v1.1.0 code and V2 roadmap audit

**Date:** 2026-09-07. **Audited release:** `v1.1.0`, commit `259e6e9`.
**Scope:** security, passive LoRa wardriving suitability, packet evidence, resource use, and V2 gates.
**Disposition:** keep the architecture; address the high-priority defects before building more behavior on it. Passing builds and existing tests do not establish capture correctness.

## 1. Assessment

The project is a sensible **single-channel passive packet receiver with deliberate, interrupting survey tools**. Radio ownership, small bounded queues, local raw-frame storage, explicit operator controls, and measurement-led RF changes are good choices for an ESP32-S3 without PSRAM. It is not a wideband packet sniffer or a calibrated spectrum analyzer. A mission profile is a listening configuration, not proof of which protocol or physical transmitter produced a packet.

The release has material defects. Cell never tunes to its reported bins. Logging can acknowledge failed writes. The bench WiFi setup discloses a supplied password. Focus can transfer coverage between different frequencies. Several fields presented as measured evidence are default values or lack the context needed for later analysis. These findings justify a maintenance pass before Field Missions and companion exports amplify them.

**The operator clarified decryption scope during this audit.** Public-channel decryption and known operator-supplied keys are permitted. Brute-force/dictionary/key-guessing recovery is out of scope. Future operator-key support requires explicit opt-in. The existing public-default-key NodeInfo decoder is therefore permitted; it is not a security finding merely because it decrypts. Guidelines were updated, with no firmware behavior or default changes.

## 3. Threat model and priorities

Treat received radio bytes, advertised names/IDs/keys, SD configuration, HTTP requests, serial frames, and imported run folders as untrusted. Attacker capabilities vary: a nearby compatible radio can inject spoofed observations; someone joining the fixed-password AP can retrieve logs and change settings; an enabled USB host has operator-like controls; a copied CSV can carry hostile spreadsheet content. Physical SD/firmware extraction remains an accepted limitation, but that does not excuse accidental key disclosure or misleading evidence.

- **High:** direct credential disclosure or materially incorrect/lost acquisition evidence; prioritize maintenance.
- **Medium:** conditional security exposure, provenance/state defects, or reliability gaps; resolve before the dependent V2 feature.
- **Low:** hardening/maintainability improvements with limited immediate impact.

These are engineering priorities, not CVSS scores. A confirmed code defect does not imply a demonstrated remote exploit.

## 4. Findings requiring maintenance

### A01 — High — Cell does not tune to its recorded frequencies

**Confirmed:** [`src/radio_task.cpp:1655–1688`](../../src/radio_task.cpp) declares `freq`, declares `int beginState;`, and compares that uninitialized variable before `startReceive()`. There is no `radio.begin()` or `setFrequency()` in the per-bin block. The explanatory comment says full initialization was restored, but the call is absent.

**Impact:** undefined behavior, premature failure, or RSSI samples at the previous frequency written under successive Cell frequencies. Cell results from this release cannot support a tower-adjacent or per-bin inference. This is separate from the already deferred Cell field-validation gate.

**Repair:** restore the intended checked tune/start sequence, then verify first/middle/last frequencies with a radio-call fake and known-frequency hardware stimulus. Include cancel, tune failure, home restore, and actual `cell.csv` contents. Treat compiler unused-variable warnings in acquisition code as actionable. Do not optimize the retune while repairing this defect.

### A02 — High — SD writes are acknowledged without checking write results

**Confirmed:** `logger_task.cpp:240–259` (`appendToFile`) ignores `f.write()`'s byte count and returns OK whenever opening succeeded. `ensureCsvLocked()` similarly ignores header `println()` results and accepts any preexisting file, including an empty or damaged header. `writeFullConfig()` and several preference writers also assume successful writes after open.

**Impact:** a full/failing card can yield zero or partial bytes while written counters increase, `sdReady` stays true, and durable-result claims appear successful. A partial row can contaminate the following append.

**Repair:** compare exact byte counts, propagate failure, distinguish partial writes, validate/create headers, and define recovery from an incomplete trailing row. Avoid blind retries that duplicate partially committed records. Verify full-card, short-write, removal, and failed-header cases. Even successful close/write is an API-level commit, not proof against arbitrary power loss inside the card controller.

### A03 — High — Bench WiFi setup prints the password it promises to hide

**Confirmed:** `scripts/heltec_wifi_setup.py:63–90` passes the entered password to `require_ack(..., "WIFI_PASS", password, ...)`. `Endpoint.request()` in `scripts/bench_harness.py` sends the complete outgoing frame to `record()`, which prints it to stdout and writes it to the supplied stream. `io.StringIO()` avoids a disk logfile but does not suppress stdout or memory retention. No redaction wrapper is installed by the setup script.

**Impact:** a real network credential can enter terminal scrollback, recorded sessions, or support transcripts. The setup docstring specifically promises the opposite. No real password was requested or used for this audit.

**Repair:** implement transport-level sensitive-argument redaction that covers retries, errors, and echoed replies. Test with a fabricated password and assert it is absent from stdout/logs/exceptions while the mock wire receives it. Review prior setup transcripts locally; rotate a credential if an exposure is confirmed. Carry this rule into future operator-key support.

### A04 — High — Focus coverage and selection confuse bin identity across regions

**Confirmed:** `FocusCoverage` (`focus_coverage.h:86–108`) keys solely on `bin_index`; `radio_task.cpp:730` passes no region, frequency, bandwidth, or configuration identity. US bin 43 is 912.750 MHz; Global bin 43 is 878.750 MHz. Both accumulate into the same label. `ui_actions.cpp:41–61` also reads the last completed peak bitmask using the **current** region rather than the region that produced that snapshot.

**Impact:** after changing Region, Focus may investigate a frequency that was never the old peak and credit it with prior observation time. This breaks W12's central promise.

**Repair:** snapshot the completed sweep's band/step/configuration and key coverage by resolved frequency plus relevant measurement configuration. Reset or reject stale selection when configuration changes. Decide separately how long coverage remains relevant while moving; three observations at distant locations must not become a single-location confidence claim. Test the exact US/Global same-index collision and changed receiver bandwidth.

### A05 — Medium — A detection formatter writes one byte beyond its advertised capacity

**Reproduced:** `detection.h:247–259` checks space for a hex byte without fully reserving the final comma and NUL. With a one-byte packet and a capacity equal to the rendered character count (64 in the reproducer), the function returns 64 and writes `out[64]=0`; it should return failure and stay within capacity. The zero-length raw case also needs a final-tail bound.

**Impact:** a real API memory-safety defect. The current logger's 768-byte buffer has sufficient margin for its normal inputs, so this audit does **not** claim a demonstrated over-air overwrite of the shipping logger.

**Repair:** check the complete tail requirement before writing and test every capacity around prefix/hex/comma/NUL boundaries, including 0/1/255-byte frames, under ASan/UBSan.

### A06 — Medium — GPS invalidation and coordinate validation can accept wrong positions

**Reproduced:** after a valid GGA followed by quality-zero GGA, `gps_parse.h:181–209` leaves `has_position=true`. `gpsFixIsFresh()` ignores `fix_quality`, so the old position remains usable until the ten-second age limit unless an invalid RMC also arrives. The reproducer returns `quality=0, has_position=1, fresh=1`. `nmeaCoordToDegrees("9900.000", 'N', ...)` also accepts latitude 99 degrees (`nmea.h:79–109`). Latitude/longitude roles and final geographic ranges are not checked.

**Repair:** revoke the position on authoritative no-fix evidence; validate coordinate grammar, hemisphere by field, finite/ranged degrees, and boundary minutes. Add missing/void RMC, bad-quality GGA, contradictory messages, and boundary tests. Do not convert a bad position to Null Island.

### A07 — High for evidence integrity — RX time and GPS attribution describe processing time

**Confirmed:** `readDetectionLocked()` stamps `rx_millis` after bus acquisition, read, and RX rearm (`radio_task.cpp:392–423`). Logger stamps the latest GPS fix at dequeue (`logger_task.cpp:388–406` and the survey/identity appenders), checking age against **now**, not the acquisition event. `GpsFix.has_time` has no independent freshness timestamp, so UTC can remain frozen indefinitely after GPS input stops. GGA time and retained RMC date can also transiently disagree at midnight.

**Impact:** queue/SD stalls move observations along a driving route; a later fix can be attached to an earlier event. Stale UTC looks authoritative even when coordinates are blank. Seconds-only timestamps limit ordering and packet-correlation work. This behavior is partly documented, but is inadequate for stronger V2 mapping claims.

**Repair:** distinguish IRQ RX-done time, queue/decode/log time, GPS-fix time/age, and UTC mapping validity. Use a small bounded timestamped fix history or explicit nearest-prior fix policy on Core 0; keep GPS locks off the radio hot path. Record uncertainty instead of inventing precise event coordinates. Test backlog, GPS loss, midnight, and uptime rollover. Wireshark similarly distinguishes timestamp precision from actual accuracy; extra digits alone do not solve this. [Timestamp reference](https://www.wireshark.org/docs/wsug_html_chunked/ChAdvTimestamps.html).

### A08 — Medium — Saved RF presets can overwrite each other; parsing is incomplete

**Confirmed:** HTTP saves use `radioActiveOverrides()`, an immutable boot snapshot (`wifi_task.cpp:346`, `radio_task.cpp:79–81`). Saving Meshtastic, then MeshCore without reboot rewrites the file from the old snapshot and loses the first save. GET returns active boot values rather than the pending saved values. `config.cpp`/HTTP parse SF/CR after narrowing to `uint8_t`, accepting values such as 263 as SF7; RF bandwidth is only required to be positive, rather than a supported finite modem bandwidth. HTTP sync-word parsing accepts trailing junk and narrows before validation. RF parsing was not part of the earlier four-preference-parser fix.

**Repair:** maintain an independently owned pending/persisted configuration snapshot or reload/merge under the writer lock, show active versus saved state, validate whole tokens/ranges before narrowing, and allowlist supported bandwidths. Test two sequential profile saves and malformed/overflow/nonfinite values. Existing web form bounds are not server validation.

### A09 — Medium — Preference updates are vulnerable to power-loss corruption

**Confirmed:** `writeProfileConfigToSD()` removes the existing config before recreating it (`config.cpp:293–296`); multiple settings writers use the same pattern. Failed recreation loses the last valid configuration. This combines with A02's unchecked writes.

**Repair:** write and validate a temporary record, close it, then replace with a recoverable backup/journal policy. Do not describe FAT rename alone as fully power-fail atomic. Test interruption at each write/replace stage and deterministic boot recovery to a known-good preset.

## 5. Security and trust findings

### A10 — Medium, accepted exposure — The field AP grants broad access through a public fixed PSK

`wifi_task.cpp:31` uses `loratrace123`; routes have no independent authentication. AP clients can download raw frames/identities/GPS and modify settings. This is disclosed in `SECURITY.md`, so it is not newly discovered secret behavior. It remains a poor default trust boundary for sensitive capture data and future keys.

Use a per-device random or operator-set credential, visible physical enable/disable, and an optional expiry policy. Separate observation access from writes. Key import must not reuse the present unauthenticated HTTP settings pattern. A small local UI does not require a cloud login or an indiscriminate TLS rewrite to improve this.

### A11 — Medium — State-changing HTTP endpoints lack request-origin/session defenses

`handleConfigPost`, `handleDisplayPost`, and `handleOptionsPost` accept ordinary form POSTs without tokens or Origin/Host validation. A browser that can reach the AP may submit cross-origin requests even when its attacker page cannot read the response. Browser private-network restrictions vary; no browser exploit was executed here.

Add a bounded per-session anti-CSRF token and appropriate Origin/Host checks; restrict expected content types/body sizes and rate-limit expensive writes. Test cross-origin forms and malformed requests. Do not rely on CORS alone to prevent mutations. [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

### A12 — Medium — Radio-controlled identity names can become spreadsheet formulas

`nodeIdentityCopyString()` removes line controls and CSV quoting doubles quotes, but leading `=`, `+`, `-`, and `@` survive (`node_identity.h:40–75`). The reproducer writes `"=1+1"` as a name. Correct CSV quotation does not stop a spreadsheet interpreting a field as a formula; exploit behavior depends on the consuming application.

Preserve literal names in canonical evidence, but provide a separate safe spreadsheet export that writes explicit text cells or neutralizes formula syntax according to the target format. Test actual export/import behavior. Future HTML reports must escape text rather than interpolate names/payloads into markup. [OWASP CSV injection](https://owasp.org/www-community/attacks/CSV_Injection).

### A13 — Medium — Protocol and identity labels overstate verification

`detectionClassification()` returns the selected profile unless `off_grid` is true (`detection.h:174–178`). Reticulum/General home channels fall back to the Meshtastic tuple (`channel_plans.h:90–103`), so matching traffic can be labeled `reticulum` without any Reticulum parser. Any 16-byte frame matching a Meshtastic receive configuration gets header fields interpreted as such. MeshCore advert parsing copies the public key and skips the signature; default-PSK AES-CTR decoding does not authenticate a sender.

Separate `listening_profile`, `protocol_candidate`, `parse_status`, and `authentication_status`. Label IDs/keys as observed claims. Use full MeshCore public keys when grouping identities, never its one-byte routing hash as a globally unique node identity. Receiver GPS locates the observation, not the originating node or tower; relays make that distinction especially important. Upstream describes the advert's signed layout, but this implementation does not verify that signature. [MeshCore payload format](https://raw.githubusercontent.com/meshcore-dev/MeshCore/main/docs/payloads.md).

### A14 — Medium — Key policy needs implementation gates, not just permission

The old no-decryption wording conflicted with the shipping NodeInfo decoder. **Policy mismatch resolved in this audit** by the operator's explicit clarification. Public-channel decoding and known operator keys are now permitted; broad/operator-key decoding is still unimplemented.

Before adding it: define input/storage/removal and opt-in UI, prevent logging/exports of keys, isolate raw bytes from derived plaintext, track decoder version and authentication outcome, bound CPU/queue costs, and use synthetic malformed fixtures. Never search a keyspace or silently try dictionaries. Publicly readable traffic still carries sensitive names, messages, and embedded coordinates. A publicly known PSK does not establish identity.

### A15 — Medium — USB authorization can expose the AP; asynchronous ON/OFF is not idempotent

Shipping `serial_control.cpp:554` implements `WIFI_SET` and earlier cases implement Sweep/SD retry, although SECURITY.md previously said AP control was unavailable. That documentation was corrected here. `WIFI_SET` reads actual `wifiIsEnabled()` then calls `wifiToggle()` on requested state. Two distinct ON commands before startup completes can toggle the request back OFF. An OFF command during pending startup sees inactive state and does nothing.

Provide `wifiRequestEnabled(bool)` with one owned requested state, and separate requested/actual/failure status. Keep the persisted physical USB gate explicit. Test ON/ON, ON/OFF before startup, and command retries with new sequence IDs.

### A16 — Medium — Bench transmission has a separate, weaker network boundary

The Heltec fixture's TCP bridge (`bench/heltec-v4r8-transmitter/src/main.cpp`, port 4227) accepts control from reachable clients without authentication. That is disclosed in its setup helper, but it is still capable of transmitting and is not covered by calling the Cardputer RX-only. Some older scripts, for example `phase9_edge_carrier_bench.py:44–60,115–156`, arm pulses without the newer explicit `--allow-transmit` gate.

Keep the bridge restricted to a trusted/isolated bench network; add explicit activation/session authorization and expiry before broader use. Apply one consistent transmit opt-in across harnesses and ensure QUIET cleanup. No transmit-capable script was executed during this audit. RX-only remains a shipping-firmware rule, not a claim that the repository contains no transmitter fixture.

### A17 — Medium — Build/release trust and reproducibility need tightening

`platformio.ini` pins the platform and GFX library but allows RadioLib/TCA8418 ranges. CI installs the newest PlatformIO; GitHub actions use mutable major tags. `build.yml` grants write permissions at workflow scope. `release.yml` rebuilds a tag without running native tests in that workflow, and direct `${{ inputs.tag }}` interpolation generates shell text. Manual dispatch is a privileged action, so this is hardening rather than an anonymous PR exploit claim.

Pin resolved tools/dependencies and action SHAs, separate read-only test/build from write-capable publishing, validate tag syntax through environment variables, and run the same tests on the exact release ref. Publish checksums and provenance for all flash parts; preserve the original artifacts when backfilling instead of silently rebuilding with drifted dependencies. The flasher's pinned-version CDN script is another supply-chain dependency worth vendoring or integrity-verifying. No specific current dependency CVE is asserted. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use).

## 6. Capture, concurrency, and resource findings

### A18 — Medium — Run folders lack self-contained build/configuration provenance

Boot/USB identify a build, but `session.csv` has no firmware revision or complete resolved configuration manifest. `detections.csv` omits `cr_denom`, `sync_word`, and channel hash despite their presence in memory. `focus.csv` omits actual receive bandwidth/SF/CR/sync, its region/step, cumulative coverage counts, and per-request radio-away time. Current configuration files at the SD root can change after a run.

Add an immutable run manifest: schema versions, build SHA/dirty status, board/RF front end, library versions, resolved modem parameters, region, capture policy, antenna context, and timestamp semantics. Record configuration changes as events. Append missing per-observation conditions rather than silently reinterpreting old columns. Exclude keys; record only nonsecret decoder configuration identifiers when necessary.

### A19 — Medium — Focus/energy evidence includes fabricated default values

`enqueueEnergyObservation()` and `enqueuePassBObservation()` explicitly set `wifi_on=false` (`radio_task.cpp:479–554`). `FocusObservation.wifi_on` defaults false and is never set in `enqueueFocusObservation()`. `qualifying_count` also remains zero even though LOG_GUIDE describes a measured count above the median-relative threshold. Partial Focus passes collect histogram samples but only a fully completed sample loop calls `focusRuntimeNoteValidPass()`, so `observation_ms` stays zero for interrupted passes. A Focus bus failure can leave `radio_status=0` because that branch sets runtime failure without updating `lastError`.

Set factual context from a bounded snapshot at acquisition time, or represent unavailable values explicitly rather than as false/zero. Track partial elapsed observation separately from valid-pass credit. Either compute the documented qualifying count without enabling an activity claim, or clearly mark it unmeasured. Test WiFi on/off, partial timeout/cancel, and bus failure rows end to end, not just formatting a manually filled struct.

### A20 — Medium — Completed Sweep data is not a coherent synchronized snapshot

The earlier audit added release/acquire fences around a **volatile** completion counter (`radio_task.cpp:1526–1555,2445–2453`). These fences do not establish the C++ atomic synchronization contract for a plain shared array. Nor do they prevent the next completion overwriting it during a multi-call read. `analyzerNoteSweepComplete()` fetches bins/capture counts individually; current region/bin count can differ from the completed data. Cancellation/failure also increments the sweep counter and publishes a partial mask, which consumers can display as a full row. Multiple completions between logger polls collapse to one row without a sequence-gap indicator.

Publish one fixed snapshot containing generation, region/step/config, sampled-bin mask, result status, start/end, peaks and between-lap captures under a short spinlock or safe buffer handoff. Copy once outside drawing. Expose skipped snapshots and partial results. Preserve the radio's bounded ownership rule; do not put display work inside the lock. A locked `radioActiveChannel()` alone also cannot give callers an atomic channel/profile pair when they separately call `radioActiveProfile()`.

### A21 — Medium — Action acceptance and recovery are inconsistent

Most legacy request functions check active flags but not other pending queues; Focus has extra pending checks. Two requests can therefore be accepted while neither action is active, then run later instead of one being visibly refused. `ulTaskNotifyTake(pdTRUE, ...)` coalesces notifications; processing one mailbox then `continue` can leave another queued request waiting until a later packet/event. The timeout branch restarts RX and continues without draining commands. A queued Focus discarded after a concurrent pause only clears `focusPending`, without a terminal result.

Profile/pause paths and normal RX rearm ignore some `startReceive()`/`sleep()` outcomes (`radio_task.cpp:408,1830–1880`). A dequeued profile switch that fails the bus lock is silently lost. A failed reconfiguration need not leave the old modem state usable.

For W13, use one bounded radio-owned command arbiter with explicit accepted/rejected/completed/failed/cancelled outcomes, drain pending commands independently of packet IRQs, and reconcile requested versus actual hardware state. Preserve the good existing restore-before-publish Focus pattern. Add a FAULT/RESTORING state when home cannot be confirmed; never infer WATCHING merely because no action is active.

### A22 — Medium — Fixed sample counts do not establish bounded radio-away time

Scope begins with a `portMAX_DELAY` wait on a Core-0-readable trace mutex (`radio_task.cpp:1770`) and can wait on that mutex while holding the shared SPI bus. Legacy actions have per-operation waits and sample bounds but not a uniform whole-action deadline. Pass-B's comment estimates 24 s from 80 × 300 ms CAD timeouts, omitting up to 80 × 2.5 s receive-on-hit windows plus retune/lock time. That arithmetic is a conservative path bound, not a measured duration.

Focus is better: it has a sampling deadline, but the final bus transaction can cross it; the deadline excludes tuning/restore, and delayed samples may execute in a burst to catch up with their old schedule. A fixed requested spacing is not proof of actual spacing under contention.

Define deadlines for total ownership, acquisition, and restore; record actual gaps/accepted samples and stop rather than backfill late sampling opportunities. Keep locks short and never wait on a display-owned data lock while holding SPI. Test worst-case CAD hits, bus delays, timeout/cancel near the last sample, and failed restore. Do not promise hard real-time bounds beyond what the driver and shared bus can enforce.

### A23 — Medium — Logger scheduling and SD operations can amplify bursts into loss

The logger receives at most one row per auxiliary queue per loop, beginning with a 100 ms wait for a detection. With no packets, auxiliary drain is roughly capped at ten rows/s before I/O. Cell emits 101 rows/lap; error or faster-retune paths change its burst rate. Directory scans, preference-file writes, and downloads also share the SX1262/SD wires, and a two-second lock-acquisition timeout does not limit how long an acquired synchronous SD operation holds them. Identity decoding currently runs on the radio task after rearm.

Measure queue occupancy/high-water marks, enqueue-to-write age, per-write **lock hold** time, and dropped rows by type. Replace serial polling with a bounded fair drain/notification policy; batch small auxiliary rows where measurement supports it. Move expanded decryption/parsing to a bounded Core-0 worker with explicit drops, not into the ISR/radio service loop. No stack reduction is justified by a build's static RAM percentage.

### A24 — Medium — HTTP downloads are incomplete and can become inconsistent

The allowlist and UI include five CSVs but omit `cell.csv` and `focus.csv` (`wifi_task.cpp:254–267`, `web_assets.h:518–533`). `streamCsvFile()` snapshots file size, then each read requests a full 512 bytes instead of `min(chunk, remaining)`. If the active file grows, the last read can send more than the declared Content-Length. `seek()` is unchecked; partial transfers are not explicitly aborted. The handler runs synchronously and never checks an AP-disable request during a long transfer. Run IDs are narrowed to `uint16_t` without checking 1–9999.

Use a shared run-file registry, strict IDs, checked seek/read and exact bounded lengths, explicit connection abort on failure, and cancel-aware transfer deadlines. Define a run export consistency point and per-file lengths/hashes; downloading each growing file independently is not a coherent run archive. Test active-file growth, slow/disconnected clients, AP disable, and all seven current CSVs.

### A25 — Medium — Run identity and recovery can merge unrelated evidence

`runNextIndex()` saturates at 9999, and the logger appends to that directory on later boots (`run_log.h:93–99`). The repeated run number does not distinguish those boots. During remount, the original run index is reused without checking card identity or establishing whether that directory is an unrelated run on a replacement card. An unavailable directory scan's fallback is also not proof of a free unique run.

Keep the friendly directory name, but add a boot/run UUID in the manifest and all joins. Fail visibly or allocate a collision-safe extension when numbering is exhausted. Verify run/card identity on recovery. Test card swaps, existing empty files, mount failure during initial directory creation, and run9999.

### A26 — Medium — Loss counters and SD-recovery narratives overclaim what is known

All unsuccessful packet reads are charged to `crcErrorCount`, including non-CRC errors; successful reads are not distinguished from failed RX rearm. Zero queue drops cannot prove that radio hardware missed nothing. `writeSessionRow()` skips when SD is unavailable, so the comment promising `sd` going down then up in the same file is not what the code writes. Session row formatting/write failures lack their own durable drop accounting.

Separate CRC/header/read/rearm failures, queue drops, logger drops, and unobservable RF opportunity loss. On recovery, write an explicit outage start/end/count summary retained in a fixed in-memory record. Define accounting invariants including buffered and queued rows. Unknown reception loss must stay unknown unless a controlled reference provides the denominator.

### A27 — Low/Medium — Parser and host-tool fuzz coverage is thin

Native tests cover useful pure helpers but do not exercise actual SD/HTTP/radio integration. The varint parser accepts an overflowing tenth byte rather than strictly rejecting malformed uint64 encodings; the MeshCore parser does not independently reject `raw_len > 255`, although current radio callers enforce that bound. NMEA helpers can silently truncate fields. These are hardening opportunities, not demonstrated shipping arbitrary-memory exploits.

Fuzz parsers and every formatter at boundary capacities using synthetic packets, ASan/UBSan, and malformed length/UTF-8/varint inputs. Add strict public parser contracts. Host `Endpoint.rx_buffer` and `observed` grow without bounds, and parsing every newline repeatedly copies bytearrays; cap retained observations and input lines for long/malicious serial or bridge streams. Test overflow resynchronization rather than accepting a valid-looking suffix of an oversized line.

### A28 — Low — Maintainability and optimization should focus on measured hot paths

`radio_task.cpp` is ~2,700 lines and `ui_pages.cpp` ~2,600, mixing state policy, acquisition and presentation details. Comments in CLAUDE's module inventory still call a Detection ~40 B even though the measured host structure is **292 B**, and old raw-payload prohibitions remain in historical module comments. Avoid carrying old measurements forward as current allocations.

Extract shared state arbitration and SD result handling before adding more branches. Keep RF algorithms and pure contracts testable. Profile redraw work, decode time, lock holds and row batching before changing buffers or radio timing. Consider compile-time exclusion of unused RadioLib protocols only as a measured flash/build-time change, not an assumed capture-speed improvement. Retain task-stack margin and inspect real stack watermarks on every deep UI path.

## 7. What should be retained

- One owner for SX1262 operations, a minimal notification-only ISR, and RX rearm before expensive queue/identity work.
- Explicit 255-byte raw-frame bound and fixed 16-entry detection queue (~4.7 KB of payload storage), separate packet/survey queues, and fixed analyzer budgets.
- Raw frame preservation and routing metadata; retain every received copy and deduplicate only in derived analysis. Relays are legitimate distinct observations.
- Distinct energy, CAD, and decoded-packet evidence. Off-grid Pass-B packets already get `unknown_lora_candidate` rather than a guessed protocol.
- Menu-controlled actions, opt-in AP, gated USB control, operator-requested SD recovery, version/tag and release-note checks.
- Real RF comparisons and deliberate retraction of overbroad claims when a second signal baseline disagreed. Keep field/bench evidence distinct.
- The stack telemetry implementation is not incorrectly scaled on this target: the installed ESP32-S3 port defines `StackType_t` as `uint8_t`, so its multiplication by `sizeof(StackType_t)` is one. Do not “fix” it from generic FreeRTOS assumptions.

## 8. RF and wardriving accuracy

The local sync constants agree with upstream: Meshtastic uses 0x2B; MeshCore selects RadioLib's private sync constant, 0x12 in the pinned driver. No sync change is recommended. [Meshtastic source](https://raw.githubusercontent.com/meshtastic/firmware/master/src/mesh/RadioLibInterface.h), [MeshCore driver](https://raw.githubusercontent.com/meshcore-dev/MeshCore/main/src/helpers/radiolib/CustomSX1262.h), [RadioLib 7.7.1 definitions](https://raw.githubusercontent.com/jgromes/RadioLib/7.7.1/src/modules/SX126x/SX126x.h).

The MeshCore advert parser's transport-code/path-size/appdata structure broadly matches current upstream documentation, including the newer encoded path hash size. Keep versioned source fixtures; this is not a signature-verification endorsement. [Packet format](https://raw.githubusercontent.com/meshcore-dev/MeshCore/main/docs/packet_format.md).

Semtech specifies 150–960 MHz coverage for the **chip**; that does not make this module/antenna/front-end combination equally sensitive across it. Preserve the project's narrower characterized ranges and the 923–928 MHz rolloff caveat. This audit did not independently calibrate them or revalidate every regional preset. [SX1262 product documentation](https://www.semtech.com/products/wireless-rf/lora-connect/sx1262).

For a wardrive, prioritize Watch on an explicitly selected real local channel. Sweep has 85 US or 221 Global bin centers at 250 kHz spacing, while receive bandwidth follows the home profile (which may be 62.5 kHz). Those centers are not complete continuous spectral coverage: bandwidth, filter rolloff, dwell, retune settling and traffic timing create gaps and biases. Pass-B uses one placeholder sync and a finite SF/BW candidate list; it cannot promise arbitrary LoRa capture or exhaustive Meshtastic/LoRaWAN discovery. Explicit-header coding rate should be recorded as configured versus observed if that distinction becomes relevant, rather than assuming the configured CR proves the transmitted one.

Noise-floor/peak thresholds describe this instrument and configuration. Repeated sampling is observation effort, not calibrated probability of absence. Do not label six samples universally inadequate or require source airtime to exceed sample spacing: a shorter burst can overlap a sample, but probability falls and depends on phase/occupancy. The failed short-dwell experiments bound those fixtures and activity rules, not every possible signal.

Cell should remain an explicitly optional **narrowband RSSI survey** after A01 is repaired. A tower-adjacent rise does not establish LTE/5G decoding, a tower identity, a distance estimate, or calibrated wide-channel power.

### Evidence wording that should be corrected in follow-up

The [run0089 soak summary](../hardware-results/2026-09-07-phase9-soak-run0089.md) supplies valuable evidence but overstates its interpretation:

- An idle tail with no allocations cannot prove absence of an allocation-triggered leak. The defensible statement is **no downward heap/largest-block trend under the exercised workload**.
- Core-0 drawing can affect logging/GPS service and thus queues/shared-resource contention; separate cores do not prove it “cannot cost a packet.”
- The ~2,650 missed-packet figure is an extrapolation from a different reference experiment and assumed comparable traffic process, not counted missed packets in that soak. Preserve it as an estimate with its assumptions.
- The 8-hour workload is primarily repeated Sweep with AP off/on, not an exhaustive Focus-with-downloads resource matrix. UI walking on a later build strengthens stack evidence but does not by itself reproduce every earlier load combination.
- Stable heap and stack minima establish observed bounds, not every possible path. The latest tests passing on `259e6e9` do not make older hardware build IDs identical to the release.

The audit leaves those historical measurement records intact; correct interpretations with dated notes rather than rewriting recorded measurements. The roadmap's W17 text was qualified during this audit to remove universal claims about airtime/sample spacing and avoid calling an unobserved frequency quiet.

## 10. Capture and companion contract recommended for V2

Keep CSV as the authoritative on-device record for now. A full pcapng implementation is not a prerequisite for good wardriving. An optional host converter may help interoperability, but it must use a documented LoRa framing/link-type contract rather than pretending these are Ethernet/IP packets or IQ samples.

| Evidence layer | Minimum contract |
|---|---|
| Raw reception | Exact bytes, captured/original lengths, RX-done monotonic time and its semantics, actual frequency/config, receive/CRC status, event ID, acquisition mode/request ID |
| Position/time | Receiver fix time/age, validity and quality; UTC mapping and uncertainty. Never imply these are the transmitting node's coordinates. |
| Run identity | Unique boot/run ID, version/schema/decoder/build provenance, immutable resolved config and append-only change events |
| Availability | Watch/survey/pause/restore/fault transitions, actual durations, observed counters, known drops and unknown opportunities |
| Derived content | Separate record linked to raw event; parse/decryption/authentication status; decoder version; no keys and no destructive rewrites of originals |
| Sharing | Explicit safe export with preview and documented removal of all location/identity/payload/key surfaces; safe spreadsheet/HTML encoding |

Keep observations of relays/replays in the raw record. Derived packet grouping can use protocol ID/from plus raw bytes, route metadata and a time window; do not delete distinct receptions just because packet IDs match. A one-byte MeshCore hash is not an identity key. Report observation coverage and opportunity denominators alongside counts. A “nothing received” report must show whether Watch was available and logs healthy.

For privacy, pseudonyms should be keyed and scoped to the intended comparison, not unsalted hashes of small node-ID spaces. Exact dates, route shapes, filenames, embedded payload positions and public keys can reidentify a redacted route. Keep originals private and let the operator deliberately choose what comparison survives the export.

## 11. Suggested repair sequence and acceptance

1. **Maintenance first:** A01–A04 and A07, plus the formatter/GPS/config defects A05/A06/A08/A09. Prioritize the password leak before further credential-bearing bench setup. Each firmware change needs a focused regression and applicable device evidence.
2. **Capture foundation:** A18–A26. Establish provenance, truthful field semantics, state snapshots, deadlines, recovery and complete exports before W13/W14 consume them.
3. **Security baseline:** AP credentials/origin controls, spreadsheet/HTML export safety, serial idempotency, consistent bench authorization and release pinning. The known-key feature must not inherit today's password-logging pattern.
4. **W17 measurement feeding W13:** compare Watch-only against proposed mission recipes with independently timed traffic, quiet/on controls, two or more signal levels, randomized timing/order and confidence intervals. Keep both raw frame success and away-time cost.
5. **W14/W15 together at their boundary:** strict importer and safe export contract first; maps, comparisons and markers follow. Validate against real old-schema folders plus fabricated damaged/adversarial fixtures.
6. **Composition evidence:** on one repaired build, exercise all actions, contention, every deep UI path, AP downloads/settings, real GPS/SD, cancellation/failure/recovery and an explicitly documented field workflow. Keep precise captures private.

No concrete stack shrink, retune speedup, or confidence threshold change is justified by this audit alone. Fix missing operations and false evidence before attempting to make them faster.
