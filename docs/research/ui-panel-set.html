On-device UI, screen by screen

LoRaTrace RX is an RX-only LoRa wardriving instrument: a Cardputer-Adv (ESP32-S3) paired with an M5Stack Cap LoRa-1262 (SX1262), read entirely from its own 240×135 panel in the field — no phone, no laptop. Every screen below is the current, shipped state of that panel: the six-page status carousel, the grouped settings menu, the boot mark, and the toast layer, reproduced at 2.2× scale with real sample data and the panel's actual RGB565 colour values.

Built for a design pass: what's here is what exists today, warts included — not a proposal. Notes on each plate call out real hardware limits worth knowing before redrawing anything.

240×135px · ST7789V2 IPS RGB565 · no alpha blending 6×8 / 12×16 fixed bitmap font, 2 sizes only TCA8418 keyboard, 4 keys + digit jumps Core 0 render loop, must not block
Plate 00

Boot mark

One-shot animated splash, own draw path (not ui_task's redraw loop) — an L-shaped trace resolves into an anchor point, three arcs sweep amber → green in sequence, then the wordmark, version, and a signal-trace flourish settle in before the boot checklist prints beneath. Shown here at its final resting frame; the three arcs replay their amber-to-green settle once on load.

Plate 01

Palette & type

Six colours, total, across the whole running UI — RGB565 has no alpha, so every state is a hard colour swap, never a tint or a fade. COL_DIM went through four revisions in one day (2026-08-29): the original mid-grey (~51% brightness) washed out under direct sunlight on a field war drive; a lighter grey (~75%) was reasoned away next, on a worry — never actually tested — that it would read the same as white under glare; a full-saturation amber fixed the sunlight problem but, seen on real hardware, was nearly as bright as the warn colour and stopped reading as "dim" at all; a muted amber toned that down but still didn't suit on taste. Landed back on the ~75% grey that was never actually field-tested the first time around — worth a real look in direct sun before the hue question gets reopened.

On-device type is a fixed Adafruit-GFX bitmap font, two sizes only: 6×8px cells (size 1, most labels/body) and 12×16px cells (size 2, hero numbers and headline words) — no italics, no weights, no third size. IBM Plex Mono stands in for it on these plates as a legible, same-proportions substitute.

Plate 3 / 6 · key 3 · shortcut S / R

Sweep

Phase 9's two-pass energy sweep, 868–923MHz. The frequency track is a position marker, not a fill/progress bar (frequency isn't a quantity being used up) — the same convention Channel's own bar uses. Warn-coloured ticks mark bins that cleared the peak threshold. “Listening to the noise, unconfirmed” (reworded 2026-08-29, same meaning as the original “energy only, not LoRa”) is deliberate: a measured RSSI peak alone is never treated as LoRa evidence on this screen. R starts repeat mode instead of one bounded pass (operator request, 2026-08-29) — back-to-back laps until R again cancels, for walking around scanning an area rather than a single war-drive check. A first attempt timed a hold on S alone and didn't work reliably on real hardware; a Ctrl+S modifier chord replaced it next, then that too was reverted (2026-08-30) after real hardware testing showed the TCA8418 can drop Ctrl's own release event, leaving repeat mode stuck on until reboot — R is a dedicated key with no release event to lose. The headline replaces the usual SCANNING/COMPLETE flicker so a continuous chain reads as one ambient scan, not a broken loop; the per-lap completion toast is suppressed too, for the same reason. The lap counter lives at the bottom of the right column, apart from peaks/best-MHz/rssi above it.

Menu 2

Brightness slider

The one slider row today. Applies live on every keypress (backlight changes as you hold), but only writes to SD once, on exiting back to the list — the same debounce point a “confirm” button would give a form. Enter and backtick/ESC both exit the slider identically as of 2026-08-29 (operator request: Enter should confirm a value, not just ESC out of it) — the SD-write debounce fires on either key now, not just BACK.

Input

Key map

Fifteen raw press bytes recognized in total, out of the TCA8418's full 56-key × press/release space — a deliberate allowlist decode, not a general keymap: every other event resolves to a no-op rather than doing something unintended. A Ctrl+S modifier chord was tried for Repeat Sweep (2026-08-29) and reverted (2026-08-30) after real hardware testing (this project's own KEY_DUMP diagnostic) showed the TCA8418 can drop Ctrl's own release event, leaving repeat mode stuck on until reboot — Repeat Sweep now uses a dedicated key (R) instead.

Read before redesigning

Hardware constraints

No alpha blending

RGB565, no per-pixel alpha. Every visual transition is a hard colour swap or a staged reveal — no fades, no translucency, no drop shadows.

Two font sizes, one face

Fixed 6×8 / 12×16 bitmap cells. No weights, no italics, no arbitrary sizing — hierarchy comes from size, colour, and position only.

240×135, fixed, no scroll

Everything on a page must fit in one frame; there is no scrolling concept anywhere in this UI.

No PSRAM

ESP32-S3FN8, ~512KB total SRAM. The off-screen canvas buffer and every allocation compete for the same small budget — this is why the heap dot/bar exist at all.

Core 0, must not block

The render loop shares Core 0 with GPS/logger/WiFi tasks and must never block on SD or radio I/O — redraws are bounded and periodic, not per-frame free-running.

Truthful visualization only

Sweep's occupancy ticks are a stored threshold-filtered fact, deliberately not a live spectrum/waterfall — a house rule against implying more precision than the data has.
