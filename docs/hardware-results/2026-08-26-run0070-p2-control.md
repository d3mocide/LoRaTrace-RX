# Phase 7 P2 control evidence — run0070 — 2026-08-26

This controlled run tested whether a settings POST leaves request state that a
following GET would release. The serial monitor attached after reset, so the
boot banner/build revision is not in this capture. The device reported
`run=70` throughout; raw serial is retained in the ignored private capture.

## Baseline

- Fresh WiFi-off baseline: 233,804 B free heap, 221,172 B largest block,
  4/178 blocks at the first AP-start checkpoint.

## Control A — settings POST, then AP off

- AP started and one browser client connected.
- One profile settings POST completed.
- AP stopped without an intentional follow-up navigation.
- After the subsequent settling sample: 212,480 B free, 159,732 B largest
  block, 28/317 blocks.

## Control B — settings POST, then dashboard GET, then AP off

- AP started from Control A's settled off-state and one client connected.
- One profile settings POST completed, followed by a dashboard request.
- AP stopped and was allowed to settle.
- After settle: 212,464 B free, 159,732 B largest block, 31/319 at the
  immediate stop checkpoint; the current-heap plateau differed from Control A
  by only 16 B.
- During the later idle tail, current heap continued recovering to 215,856 B
  (no AP active), so the first 30–60 seconds are not a sufficient final
  off-state settling window.

## Interpretation

The explicit follow-up GET did not recover a measurable amount relative to
Control A at the initial stop checkpoint, so request-state retention is not
the primary explanation for the earlier run0069 post-browser delta. The later
rise from 212,464 B to 215,856 B shows that WiFi-off teardown/coalescing can be
slow; a minimum five-minute off-state sample plus fresh no-client and
client-only cycles are required before labeling the remaining difference a
leak or a permanent client cost.

All data-path counters remained zero; no CSV or long-transfer workload was
used in this control.

**P2 control: request-state hypothesis not confirmed; delayed lifecycle
recovery remains open.**
